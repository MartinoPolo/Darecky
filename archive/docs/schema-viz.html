Soft Delete Strategy

Convention

All core domain tables have a deleted_at timestamptz column (NULL = active). Queries must filter WHERE deleted_at IS NULL unless explicitly showing deleted records.

Table Soft Delete Semantics
wishlist Owner "deletes" a wishlist – hidden from all views, data preserved
gift Moderator removes an unreserved gift – reversible undo
reservation Unreserve = soft delete (preserves history for moderators)
like Unlike = soft delete (preserves notification history)
moderator_assignment Owner revokes moderator – preserves audit trail

Exceptions (no soft delete): priority_level (replaced inline), moderator_invite (has revoked_at), wishlist_follower (has unfollowed_at), notification (hard-deleted after 1 year by cron).

Key Invariants & Constraints

Owner NEVER sees reservation state All queries for wishlist owner must exclude reservation data. No reservation counts, no gifter names, no reserved/free indicators. This is the CORE product invariant.
Owner cannot reserve on own wishlist Enforced at app level. Owner is the "recipient" role – if they want to reserve, they follow someone else's list.
Sharing locks owner editing When wishlist.status = 'active' (shared_at IS NOT NULL), owner can only INSERT new gifts. UPDATE and DELETE on existing gifts are blocked for owner role.
Reserved gifts cannot be removed Moderators cannot soft-delete a gift that has any active reservations (WHERE deleted_at IS NULL). Must contact gifter first.
Owner self-promote is IRREVERSIBLE Once owner_is_moderator = true, it cannot be set back to false. Triggers notification to all followers. Shows permanent banner on wishlist.
Reservation quantity ≤ available SUM(active reservation.quantity) for a gift must not exceed gift.quantity (when not NULL/unlimited). Enforced at app level with soft-delete filter.
Anonymous identity constraint CHECK: reservation.user_id IS NOT NULL OR reservation.anonymous_name IS NOT NULL. Every reservation must have an identifiable actor.
Auto-follow on reservation When an authenticated user creates a reservation, upsert into wishlist_follower (clear unfollowed_at if re-following).
Archived = read-only When wishlist.status = 'archived', no new reservations accepted. Existing data is preserved as-is.
Soft-delete queries must filter All standard queries must include WHERE deleted_at IS NULL. Only admin/audit views may show soft-deleted records.

Visitor Reserves a Gift

1
Visitor clicks "Reserve" on gift (authed or anonymous w/ name)
2
Check: user is NOT the wishlist owner
3
Check: gift.quantity IS NULL (unlimited) OR SUM(active reservations) + requested ≤ gift.quantity
4
INSERT into reservation (user_id or anonymous_name + anonymous_email)
5
If user is authenticated → UPSERT into wishlist_follower (clear unfollowed_at)
6
Query: any active like rows for this gift_id WHERE user_id ≠ reserver?
7
For each liker → INSERT notification (type: liked_gift_reserved, email_sent: true)
8
For each active follower (excl. reserver + owner) → INSERT notification (type: gift_reserved, email_sent: false)

Visitor Unreserves a Gift

1
Visitor clicks "Unreserve" on a gift they reserved
2
UPDATE reservation SET deleted_at = now() WHERE id = :id AND deleted_at IS NULL
3
Gift's available quantity recalculated (SUM of active reservations decreases)
4
No notification triggered (unreserve is silent)

Owner Shares Wishlist

1
Owner enters sharing wizard (Step 1: confirm lock)
2
UPDATE wishlist SET status = 'active', shared_at = now()
3
From this point: owner can only INSERT new gifts (edit/remove locked for existing)
4
Step 2: choose sharing method → Step 3: success with clear text about restrictions
5
Social sharing via intent URLs (WhatsApp, email, Telegram, SMS, copy link)

Moderator Edits/Removes a Gift

1
Check: user has active moderator_assignment (deleted_at IS NULL) for this wishlist
2
Check: if removing – gift has no active reservations (deleted_at IS NULL). Block if any.
3
UPDATE gift (edit) or SET gift.deleted_at = now() (soft remove)
4
If UPDATE and gift has active reservations → find reservers
5
For each reserver → INSERT notification (type: reserved_gift_edited, email_sent: true)
6
If reserver has anonymous_email → send email to that address too

Owner Archives Wishlist

1
Owner clicks "Archive" (or prompted after event_date passes)
2
UPDATE wishlist SET status = 'archived', archived_at = now()
3
No new reservations accepted (enforced at app level)
4
For each active follower → INSERT notification (type: wishlist_archived, email_sent: true)
5
Wishlist rendered with archived treatment (desaturated, dimmed in dashboard)

Unfollow / Refollow a Wishlist

1
User clicks "Prestat sledovat" on a followed wishlist
2
UPDATE wishlist_follower SET unfollowed_at = now() WHERE wishlist_id = :wid AND user_id = :uid
3
Wishlist disappears from Sledovane page (default view)
4
User enables "Zobrazit opustene" toggle → unfollowed lists appear dimmed
5
User clicks "Znovu sledovat" → UPDATE SET unfollowed_at = NULL
6
Wishlist reappears in active Sledovane view, notifications resume

Index Strategy

Performance-Critical Queries

Query Index
Active gifts by wishlist (sorted) gift(wishlist_id, sort_order) WHERE deleted_at IS NULL
Active reservations for a gift reservation(gift_id) WHERE deleted_at IS NULL
User's active reservations reservation(user_id) WHERE deleted_at IS NULL
User's active followed wishlists wishlist_follower(user_id) WHERE unfollowed_at IS NULL
User's unfollowed wishlists wishlist_follower(user_id) WHERE unfollowed_at IS NOT NULL
Unread notifications notification(user_id, read) WHERE read=false
Wishlists by owner (active) wishlist(owner_id, status) WHERE deleted_at IS NULL
Likes for notification check like(gift_id) WHERE deleted_at IS NULL
Active moderator check moderator_assignment(wishlist_id, user_id) WHERE deleted_at IS NULL
Priority levels for wishlist priority_level(wishlist_id, sort_order)
Notification cleanup (cron) notification(created_at) – for DELETE WHERE created_at < 1yr

Unique Constraints (partial)

Table Columns Condition
like (gift_id, user_id) WHERE deleted_at IS NULL
moderator_assignment (wishlist_id, user_id) WHERE deleted_at IS NULL
wishlist_follower (wishlist_id, user_id) composite PK (always unique)
moderator_invite (token) always unique
priority_level (wishlist_id, sort_order) –

Partial unique indexes (WHERE deleted_at IS NULL) allow soft-deleted duplicates while preventing active duplicates.
