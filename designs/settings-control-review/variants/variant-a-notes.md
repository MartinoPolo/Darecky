# Variant A — explicit staged controls

- **Source mapping:** Parent lifecycle mirrors `WishlistSettingsModal.svelte` and `WishlistSettingsSaveButton.svelte`; category drafts mirror `WishlistCategorySettings.svelte`; controlled palette and picker behavior follows `WishlistPalettePicker.svelte` (`value`, `onchange`, `disabled`) and `ColorPicker.svelte` (`value`, `label`, `disabled`, `onValueChange`).
- **Controls:** Start on **Kategorie** and open any bordered color chip. Presets, hex, and the native color control modify only the picker draft; **Uložit** accepts it into the settings draft and **Zrušit**, Escape, or outside click discards it. **Vzhled** contains all ten fixed-width, centered palette choices. The pinned footer performs the simulated global save.
- **Lifecycle:** Tab changes preserve the parent draft. Closing dirty settings opens Save/Discard/Continue editing; a save failure retains the draft. Picker dismissal restores focus to the current trigger, topmost layers trap focus, and Escape dismisses the topmost layer first. Pending save freezes edits, reset, fixtures, and exits against a captured submission baseline.
- **Review fixtures:** The separate collapsible ledger truthfully shows saved/settings/picker values and starts collapsed on phones so it cannot cover the pinned global Save. Its light/dark control uses canonical tokens; Data/Loading/Empty expose category specimens, and “chyba uložení” makes the next global save fail.
- **Limitations:** “Saved” means in-page memory only and resets on reload; this prototype does not claim persistence. Native browser color dialogs vary by OS, and selecting there still requires the picker’s own **Uložit**. Category enablement and context-only tabs intentionally remain noninteractive.
